You are deploying the Secure & Private by Design scaffolds. The user has already run `/sbd-init` and there should be a `privacy-security-manifest.yaml` at the project root.

## Pre-flight

1. Read `privacy-security-manifest.yaml`. If missing, tell the user to run `/sbd-init` first and stop.
2. Note the stack, regimes, and data categories.
3. For each regime, load the matching `regimes/<id>.yaml` from the plugin directory to find which controls apply.

## Product-code scaffolds

The engine copies these, so the result does not depend on who runs it. Do not write scaffold files yourself.

1. Call `sbd_plan_deploy`, or run `node "${CLAUDE_PLUGIN_ROOT}/dist/sbd.mjs" deploy --dry-run`. Both write nothing. The plan gives an `action` for each scaffold the manifest requires:

   | action | meaning |
   |---|---|
   | `create` | missing; will be copied from `templates/<stack>/` |
   | `update` | deployed earlier, not edited, and the template has changed |
   | `none` | deployed and up to date |
   | `skip` | an edited file, a user-authored file, or the scaffold exists under another accepted name |
   | `overwrite` | as `skip`, but replaced because `--force` is set |
   | `blocked` | could not be deployed: no template for this stack, or an unsafe path |

2. Show the user the plan.
3. Run `node "${CLAUDE_PLUGIN_ROOT}/dist/sbd.mjs" deploy`. It is safe to re-run.
4. Add `--force` only if the user asks for it for files they have named. It replaces their edits. It never touches a scaffold under another accepted name, and it never writes through a symlink.

Which scaffolds apply comes from the `when:` conditions in `rules/scaffolds.yaml` and the manifest's regimes and data categories. The stack comes from `--stack`, then `product.stack`, then detection; `sbd deploy` stops if none of them gives an answer.

Templates exist for `typescript-express` and `python-fastapi`; `typescript-nextjs` has none yet, so its scaffolds show as `blocked`. Scaffolds land under `src/privacy/`, `src/security/` and `src/ai/`, as `.ts` or `.py` files.

**Python notes (`python-fastapi`)**
- Scaffolds need Python 3.10+ and `fastapi`. Add `fastapi` to the project's dependencies if it is missing.
- They use relative imports (`from ..security.audit_log import audit_log`), so the folder holding `privacy/`, `security/` and `ai/` must be imported as a package. Run from the project root (`uvicorn src.main:app`), not with `src` on `PYTHONPATH`.

## Deployment rules

1. **Stamped.** Every deployed file keeps the template's generator header and gains the template's checksum below it:
   ```
   // Generated by secure-by-design v0.1.0 for ISO 27001 A.5.15 / A.8.3 (Access Control).
   // Template checksum: sha256-<64 hex characters>
   ```
   Python files use the same lines with `#` comments.

   On a re-run, a file whose content still matches that checksum is untouched and can be updated. A file that does not match has been edited, and a file with no checksum is user-authored. Both are left alone without `--force`.

2. **Never silent overwrite.** If the plan shows `skip`, tell the user, and do not work around it.

3. **Report** what the command printed, then point to `/sbd-check`.

## Dev-loop artifacts

`sbd deploy` covers the product-code scaffolds only. Offer these separately:

- `.github/PULL_REQUEST_TEMPLATE.md` — append (don't overwrite) the regime checklist
- `.github/workflows/secure-by-design.yml` — CI job that runs the plugin's checks
- `.husky/` or equivalent — wire up pre-commit hooks (or add to existing config)

## What to NEVER deploy

- HIPAA, GDPR, EU AI Act, or any regime not in the manifest. Even if the user's data smells like it should trigger one, the user picks regimes, not the plugin.
- Scaffolds for stacks not in the manifest. If user is on Go and the plugin doesn't support it yet, report what's missing instead of guessing.
- Production secrets. Every scaffold uses `process.env.*`, `os.environ` or equivalent. Never hardcode.
