# Contributing

Thanks for helping. Bug reports, new rules, regime corrections and scaffolds for new stacks are all welcome.

## Set up

You need Node.js 20 or later and Python 3.10 or later. Set `SBD_PYTHON` to choose the interpreter.

```bash
npm ci
npm test
```

`npm test` type-checks the engine, confirms `dist/` matches the source, type-checks the TypeScript and Python scaffolds, and runs the test suite against fixture projects. The first run builds a private virtualenv in `build/` from a hash-pinned lockfile, so it needs network access.

## Where things live

| Path | What it holds |
|---|---|
| `mcp-server/src/core/` | The engine: check, scan, validate, plan, explain |
| `rules/*.yaml` | Check rules as data. Add a rule here and every adapter picks it up |
| `regimes/*.yaml` | Regime catalogues |
| `schemas/` | JSON Schemas for the manifest, regimes and rules |
| `templates/` | Scaffolds and instruction packs copied into user projects |
| `instructions/agent-instructions.md` | The single source for the generated `.claude/CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, Copilot and Cursor files |
| `dist/` | Committed bundles, not minified, so installs need no build |

## Before you open a PR

- Run `npm run build` after changing anything in `mcp-server/src/`. `npm test` fails if the bundles are stale.
- Run `npm run gen:instructions` after changing `instructions/`, then `npm run check:instructions`.
- Add or update a test in `mcp-server/test/` for any change in behaviour. A new rule needs a fixture that triggers it.
- Do not edit `regimes/ai-security-wiki.yaml` or `rules/ai-wiki.yaml` by hand. They are generated by `npm run sync:wiki` and licensed under CC BY-SA 4.0 (see [NOTICE](./NOTICE)).

## Commit messages

Every commit message needs an authorship provenance tag or an `AI-Assistance:` trailer. The `commit-msg` hook rejects commits with neither:

- `[human]`
- `[ai-human-pair]`
- `[ai:<tool>]`, for example `[ai:claude-code]`

## Accuracy rules

This project maps code to laws and standards, so wording matters.

- Never say a project, scaffold or check makes anything compliant or certified. Compliance is a legal determination. See [LEGAL-DISCLAIMER.md](./LEGAL-DISCLAIMER.md).
- Enforce only the regimes a manifest lists.
- Never classify a field as personal or sensitive on the user's behalf.
- `sensitive-personal` is this tool's own tier. The DPDP Act 2023 has no "sensitive personal data" category, and s.7 has no general "contract" ground.
- Cite a clause only when you have checked it against the primary text.
